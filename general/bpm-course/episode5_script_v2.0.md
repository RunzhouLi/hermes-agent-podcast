## 本集摘要

上一集结尾我们埋了个"+"号，说留到后面专门讲——这一集就是兑现。光会画"顺利演完"的流程图还不够，真实的业务总会出意外：演到一半要拉幕停演、后台临时要加一段救场、台上某句词演砸了要急救、甚至有一幕已经演完了还得"返场补救"。本集顺着这条"出意外、要撤销、要善后"的主线，依次拆六件 BPMN 高级工具：终止事件（Terminate Event）、事件子流程（Event Sub-Process）、文本注释（Text Annotation）、边界事件（Boundary Event，含消息/定时/错误/信号/补偿五型）、错误事件（Error Event，抛出与捕获、错误码、传播）、以及补偿（Compensation，撤销已完成的工作）。最后用练习把多实例 vs AND、以及两道选作答案 5.2、5.3 串成建模检查站。全集的心智模型只有一个：**流程是一场已经开演的舞台剧**。

---

## 本集学习目标

1. 解释终止事件的语义（清空当前（子）流程及其所有子流程的全部令牌、向环境发出"坏结局"信号），并与普通结束事件区分
2. 理解事件子流程（由事件触发而非由令牌进入、虚线外框、无进出顺序流），区分中断型与非中断型
3. 知道文本注释是注解（用关联线连接、不影响令牌流）
4. 掌握边界事件五种类型：消息、定时、错误、信号、补偿，并区分中断型（实线）与非中断型（虚线）
5. 理解错误事件：抛出（必带错误码标签）与捕获（带标签只捕该码、不带标签捕任意），以及错误向最近匹配边界事件的传播
6. 理解补偿：撤销已经完成的工作、补偿处理器用关联连接且无顺序流、补偿的触发与连接
7. 辨清三组关键区分：补偿 ≠ 错误处理、终止 ≠ 普通结束事件、事件子流程 ≠ 边界事件

## 本集术语表

| 中文 | English | 缩写/标记 | 通俗解释 |
|---|---|---|---|
| 终止结束事件 | Terminate End Event | 实心黑圈 | 一声令下，把当前（子）流程及其所有子流程的令牌全部清空 |
| 普通结束事件 | None End Event | 细线空圈 | 只消耗到达它的那一个令牌，别的路照走 |
| 事件子流程 | Event Sub-Process | 虚线外框 | 父流程运行期间由事件触发的一段处理逻辑，不靠令牌进入 |
| 触发器 | Trigger | — | 启动事件子流程的事件（消息/定时/错误/信号等） |
| 文本注释 | Text Annotation | 方括号 [ | 给图加批注，用关联线连，不影响令牌流 |
| 关联 | Association | 点线 | 连注释或补偿处理器，不携带令牌 |
| 边界事件 | Boundary Event | 贴在活动边框的圆圈 | 活动执行期间监听某个触发器 |
| 消息边界事件 | Message Boundary Event | 信封 | 活动进行中收到消息就触发 |
| 定时边界事件 | Timer Boundary Event | 时钟 | 活动超时触发（EP04 已讲） |
| 错误边界事件 | Error Boundary Event | 三角/闪电 | 捕获活动内部抛出的错误 |
| 信号边界事件 | Signal Boundary Event | 三角 | 捕获广播出来的信号 |
| 补偿边界事件 | Compensation Boundary Event | 倒带 ◀◀ | 标记某活动"可被补偿"，挂上撤销逻辑 |
| 中断型 | Interrupting | 实线圆圈 | 触发即取消当前活动，转异常路径 |
| 非中断型 | Non-interrupting | 虚线圆圈 | 触发时活动继续，并行开一条新路径 |
| 错误事件 | Error Event | 闪电 | 用来表达失败并恢复 |
| 抛出错误 | Throw Error | 实心闪电 | 必须带一个错误码标签 |
| 捕获错误 | Catch Error | 空心闪电 | 带标签只捕该码，不带标签捕任意错误 |
| 错误传播 | Error Propagation | — | 由最近的、带匹配边界事件的父层来处理 |
| 补偿 | Compensation | 倒带 ◀◀ | 撤销已经完成的工作 |
| 补偿处理器 | Compensation Handler | 用关联连接 | 真正执行"撤销"动作的活动，没有顺序流进出 |
| 多实例 | Multi-instance | ∥ 两竖线 | 对一组对象各起一份实例（EP04 已讲，本集习题复用） |

## 完整双主持稿

**[开场音乐淡入]**

**A:** 欢迎收听《BPM 流程解码》，我是晓雨。

**B:** 大家好，我是老师。晓雨，上一集结尾我留了个钩子——子流程标记里那个"+"号，我说留到后面专门讲。这一集就来还债。这周你又拿什么练手了？

**A:** 我把客服工单暂时放一边，画了个更大的——电商的采购订单履约流程。检查订单、备货发货、处理付款，最后订单完成。一条主线顺顺当当，我画得特别得意。

**B:** 然后呢？我猜你又撞墙了。

**A:** 何止撞墙，是连撞了四种我以前从没想过的情况。第一种：检查订单的时候发现客户负债太高，这单根本不该继续，可我后台还并行跑着一个"评估房产价值"的任务——我想"啪"一下把整摊全停掉，可普通的结束事件做不到，它只停了它那一条路，另一条还在跑。

**B:** 记住这个"想一键全停、可它只停一条路"的憋屈感。这是今天第一件工具的胃口。继续。

**A:** 第二种：订单都处理到一半了，客户突然发来一条"我要改收货地址"。这不在我主流程的任何一个岔路口上——它是**随时可能从天而降**的。我不知道该把它接在哪。第三种：备货那一步，深深嵌在好几层子流程里头，万一"缺货"了，这个"出错"的消息怎么从最里层冒出来、谁来接？第四种最要命——

**B:** 等等，第四种我替你说：客户已经**付完款、货也发出去了**，结果他要取消。这时候你没法假装无事发生，钱得退、货得往回收。已经演完的一幕，要"倒带补救"。

**A:** 对！就是这个。普通流程图全是"往前走"，可这四种全是"往前走"装不下的。

**B:** 好。那我先给你一副今天通用的眼镜，戴上它，这四种情况会突然变得好理解。**把一个正在运行的流程，想象成一场已经开演的舞台剧。**

**A:** 已经开演的舞台剧……为什么强调"已经开演"？

**B:** 因为今天所有工具的难点，都在于"戏已经在演了"。戏没开演，怎么改剧本都行；可大幕一拉开、演员一上台，你再想干预，就得有专门的章法。顺着这副眼镜：你的第一种情况——发现这戏没法演下去了，要**中途拉幕、宣布停演**，那是**终止事件**。第二种——演出途中后台**临时塞进来一段加演**，那是**事件子流程**。第三种——台上有句词**演砸了**、后台得有**急救方案**，那是**错误事件**，而接住它的地方是**边界事件**。第四种——有一幕**已经演完了**，现在要**返场把它补救回来**、给观众**退票退款**，那就是**补偿**。

**A:** 哦——这么一摆，四种情况其实是一条线：从"还没演完就喊停"，到"演到一半救场"，再到"演完了还得返场补救"。

**B:** 正是这条线。我们就顺着它走。先拆最干脆的那件：拉幕停演。

### 【第一段】拉幕停演：终止事件 Terminate Event

**B:** 回到你那个憋屈的场景：检查订单发现负债太高，你想一键停掉整摊，可普通结束事件只停了一条路。先问你——你觉得普通结束事件，到底"消耗"掉的是什么？

**A:** 是……到达它的那个令牌？哪条路的令牌走到了这个结束圈，就把那个令牌收掉。

**B:** 完全正确。这正是它的局限。在 BPMN 里，普通结束事件——英文叫 **None End Event**，画成一个**细线空心圆圈**——它的语义是"**只消耗到达我这里的那一个令牌**"。你后台并行跑着的"评估房产价值"，它那个令牌根本没走到这个结束圈，所以它**照跑不误**。

**A:** 所以我画一百个结束事件，也只是把一条条路各自收掉，整场戏并不会停。那……有没有一种"总闸"，啪一下全黑灯？

**B:** 你又把答案的形状描出来了。这就是第一件工具：**终止结束事件**，英文 **Terminate End Event**。图形是一个结束圈，但里头是一个**实心的黑圆点**——你可以把那个黑点想成"全场断电"的总开关。课程给了它精确的三句语义：第一，它**清空当前流程及其所有子流程里的全部令牌**；第二，**它的父流程照常继续**；第三，它**向环境发出一个"坏结局"的信号**。课程还专门加了一句忠告：**慎用**。

**A:** 我得逐句嚼一下。"清空当前流程及其所有子流程的全部令牌"——就是不管现在还有几条路在跑、跑到哪了，全部作废，对吧？这就是我要的总闸。

**B:** 对。这就是它和普通结束最硬的区别：普通结束**只收一个令牌**，终止**清空整个范围**。用舞台剧的话——普通结束是"**一个演员下场**"，戏照演；终止是"**舞台监督拉幕、宣布本场停演**"，所有还在台上的演员，不管演到哪，全停。

**A:** 那第二句"父流程照常继续"我有点卡。既然全停了，怎么还有东西继续？

**B:** 关键在"当前范围"四个字。终止只清空**它所在的那个（子）流程**和**它下面嵌套的子流程**。如果这个终止事件是搁在一个子流程里头的，那它停的是这个子流程这一整摊；可包着它的那个**外层父流程**，不在它的清空范围里，照常往下走。就像剧中剧——里头那出小戏停演拉幕了，但**外面的大戏**还接着演。

**A:** 懂了。是"**往下全清、往上不动**"。范围就到当前这一层和它的内层为止。

**B:** 漂亮。现在把它落到课程那个房贷的例子上，正好就是你的场景。流程一开始是个 AND 并行分叉——一边"检查负债"，一边"评估房产价值"，俩同时跑。检查负债那边接一个 XOR：负债高，还是负债低？**负债低**就往下走，和房产评估汇合，最后"发放房贷"。**负债高**呢——直接接一个**终止事件**。

**A:** 我来接：负债一旦判定为高，根本没必要再评估房产了，所以终止事件啪一下把"评估房产价值"那条还在跑的令牌也一起清掉，整个房贷申请当场停演，对外发出"这单黄了"的坏结局信号。要是用普通结束，房产评估还会傻乎乎地跑完——纯属浪费。

**B:** 一字不差。那"慎用"这句，你品出味道了吗？

**A:** 我猜……因为它太霸道了？一拉幕全停，要是用多了，图里到处是"总闸"，别人根本看不清正常流程到底长什么样，也搞不清哪些路是被它强行掐断的。

**B:** 正是。终止是把锋利的刀，专治"再演下去毫无意义"的死局，但你不能拿它当普通收尾用。一句话锁死：**普通结束收一个令牌、戏照演；终止清空整个范围、拉幕停演——而且慎用。**

### 【第二段】临时加演：事件子流程 Event Sub-Process

**B:** 停演解决的是"不演了"。可你第二种情况不是不演——是**戏照演，但中途客户发来"改地址"，得临时插一段处理**。这条消息不在你任何一个岔路口上，它随时可能来。先问你：这种"随时可能从天而降、得临时处理一下"的东西，你会想怎么在图上安顿它？

**A:** 我一开始想画个岔路口去等它……但岔路口是固定在某个位置的，它管不了"随时"。要不……我专门搭一个小台子，平时空着，消息一来就在那个小台子上演一段？

**B:** "专门搭一个小台子、平时空着、触发了才演"——这就是**事件子流程**，英文 **Event Sub-Process**。它和普通子流程长得像，但有一处**致命的不同**，课程把它点得很透：**普通子流程是靠"令牌"走进去的；事件子流程是靠"触发器"启动的。**

**A:** 触发器，**Trigger**。所以普通子流程是"令牌走到门口、推门进去"；事件子流程没有门、没人推它，是"外面发生了某件事，它自己就启动了"？

**B:** 正是这个体感。也正因为这样，它在图上有三条铁律。第一，图形上它是**整个外框都画成虚线**的一个子流程框——虚线就是在喊"我不是主流程的一部分"。第二，它**搁在某个流程或子流程的内部**，是那场戏的"内置加演节目"。第三——也是最反直觉的——它**没有进出的顺序流**：没有箭头指进它，也没有箭头从它指出来。

**A:** 没有进出的箭头，这个我必须停一下。普通的活动都是靠箭头串起来的，它怎么能"悬空"在那儿？

**B:** 因为它根本不在令牌流上。普通活动要靠顺序流把令牌递进来；可事件子流程是**等触发器**的，触发器一到它自己就开演，不需要谁把令牌递给它。就像舞台剧里的**临时加演**——它不接在主线剧情的任何一句台词后面，是后台一声令下"加演开始"，它自己就上了。

**A:** 那它演的时候，主线那出戏怎么办？是停下来等它，还是各演各的？

**B:** 这就是它最重要的分叉，而且你应该眼熟——上一集我们在边界定时事件上见过这对孪生兄弟：**中断型**和**非中断型**。课程对事件子流程是这么界定的：**中断型**，启动它的开始事件画**实线**，语义是"**清空父流程的所有令牌，然后接着正常走**"——也就是主线先叫停，转由这段加演接管。**非中断型**，开始事件画**虚线**，语义是"**对父流程毫无影响**"——主线照演，加演在旁边并行加一段。

**A:** 我用改地址这个例子分两种情况演一遍：如果设成**中断型**，那"改地址"消息一到，当前正在跑的订单处理**全部叫停**，先把地址改对、再按新地址重走——因为地址错了继续处理没意义。如果设成**非中断型**，那就是**一边继续处理订单、一边并行把地址悄悄改掉**，主线一点不耽误。

**B:** 两种都说得准。课程那张采购订单的例子里，地址变更就是作为一段事件子流程挂进去的：主线是"收到 PO → 登记 PO → 检查可用性 → 发出 PO 响应"，而"收到地址变更"这个触发器，启动的是一段独立虚线框的加演——改地址、地址改完。选中断还是非中断，取决于业务上"改地址要不要打断当前处理"。

**A:** 那我又要问一个上集结尾埋的问题了：非中断型边界定时是**虚线圆圈**，事件子流程也是**虚线**——这俩到底怎么分？

**B:** 你记性真好，正好把上集的伏笔接上了。区别就一句话：**虚线如果是贴在某个活动边框上的一个小圆圈，那是非中断型边界事件，它附着在单个活动上；虚线如果是整整一个框，框里装着一段完整的处理逻辑、还不接在任何活动上，那是事件子流程。** 一个是"贴在活动边上的小圆圈"，一个是"整框虚线的一段加演"。

**A:** 锁死：虚线**小圆圈贴边** = 非中断边界事件；虚线**整框独立摆** = 事件子流程。

**B:** 记住了这条，今天后面就不会乱。

### 【第三段】剧本批注：文本注释 Text Annotation

**B:** 在往"出错急救"走之前，插一件最轻巧的工具——它跟令牌流毫无关系，但你画图时天天要用。还是用刚才那张采购订单图：你想在"检查可用性"旁边写一句"此处需人工复核高额订单"，给读图的人看。你会怎么加？

**A:** 我直觉是再画个活动……但它不是一个"动作"，就是一句**说明**。画成活动的话，令牌还得走进去，那不就改了流程？

**B:** 你这个警觉非常对。这就是**文本注释**，英文 **Text Annotation**。课程给它的定性只有一句，但分量很重：**文本注释是注解，它不影响令牌流。** 图形上是一个**开口的方括号"["**，里头写你的批注，再用一条**关联线**——英文 **Association**，画成**点线**——把它连到任何你想注释的元素上。

**A:** 关联线，点线。我把上一集那个对子拽出来对一下：实线是顺序流、推令牌；虚线箭头是数据关联、管读写；那这个**点线关联**呢？

**B:** 好，把三种线一次摆清：**实线箭头**是顺序流，**推令牌、推流程**；**虚线箭头**是数据关联，**连数据、表示读写**；**点线**是关联，**连注释**——而且它**什么都不推**，纯粹是给人看的。用舞台剧讲，文本注释就是**剧本页边上的批注**：导演写给自己和演员看的提示，观众根本看不到，它一个字都不会改变台上演什么。

**A:** 所以它能连到任何东西上，活动、事件、网关、连线都行，因为它本来就不参与执行，纯注解。

**B:** 正是。一句话带过：**点线连批注，注释不动戏。** 这件小工具就这么多。但你别小看它——等下讲补偿的时候你会发现，那条"点线关联"还会以另一个身份出现，到时候我提醒你。

### 【第四段】后台事故处理：边界事件 Boundary Event 总览

**B:** 现在进正题里最像"应急系统"的一块。回到你第三种情况——备货时可能缺货、客户可能中途取消。这些都是"**活动正在进行的过程中，外头突然有事**"。先问你：上一集我们学的捕获中间事件，是在**什么时机**起作用的？

**A:** 中间捕获事件是站在**主流程线上**的，令牌走到它那儿，它才开始等、开始接。是"走到这个点"才生效。

**B:** 准确。那问题就来了：你的"缺货""客户取消"，不是发生在某个**点**上，而是发生在**一个活动正干着的整段时间里**。一个站在点上的中间事件，接得住吗？

**A:** 接不住……它得是个能"在活动干活的**整个期间**都竖着耳朵"的东西。

**B:** 这就是**边界事件**，英文 **Boundary Event**。课程把它和中间捕获事件并排对比，一句话点破区别：**捕获中间事件，在某些点上响应触发器；边界事件，在活动进行期间响应触发器。** 图形上，它是一个**贴在某个活动方框边框上**的圆圈——所以叫"边界"，它就长在活动的边上。

**A:** 长在活动边框上……我想象一下：一个任务方框，边上骑着一个小圆圈，圆圈引出一条路通向别处。活动正常干完，这圆圈就作废；活动干到一半触发器响了，就从这条路杀出去处理。

**B:** 体感完全对。这正是舞台剧里**后台随时待命的事故处理流程**：一幕戏正在演，后台守着好几个应急按钮——着火了、演员晕倒了、观众闹事了——哪个按钮被按下，就从后台拉出一条对应的处理流程。课程先用一个**消息边界事件**的例子打样：报价到下单的流程里，主线是"准备报价 → 收到订单 → 发货 → 归档订单"；而在这中间挂了一个**消息边界事件"取消采购单"**——只要客户在这期间发来取消，边界事件就触发，转去"处理取消"。

**A:** 所以"客户随时可能取消"这种事，用边界事件正好——它在整段处理期间都守着。那它和上一段的事件子流程，不会又打架吗？都能处理"中途来的消息"啊。

**B:** 好问题，这是今天第三组要分清的。**边界事件贴在某一个具体活动的边框上**，它守的是"**这个活动**进行期间"；活动一结束，它就下岗了。**事件子流程**是整框虚线、搁在整个（子）流程内部，它守的是"**整个流程**运行期间"，不绑定某一个活动。一个是"给**单个活动**配的应急按钮"，一个是"给**整场戏**配的内置加演"。

**A:** 懂了。范围不一样：边界事件管一个活动的窗口，事件子流程管整场的窗口。

**B:** 对。接着看边界事件的两个维度。第一个维度你已经在 EP04 见过，照样适用：**中断型**和**非中断型**。课程原话：非中断型边界事件"**不会从所附着的活动上移走令牌**"，语义和定时那对一样。**中断型画实线圆圈**——触发即**取消当前活动**，令牌转异常路径；**非中断型画虚线圆圈**——触发时活动**照常继续**，同时**并行**拉出一条新路。

**A:** 套到取消订单上：如果"客户一取消，当前的备货发货立刻停、转去处理退单"——那是**中断型**，实线圈，原活动停了。如果"客户发来催促，给客服提个醒，但备货**继续**"——那是**非中断型**，虚线圈，活儿没停。跟上集定时那对一模一样的逻辑。

**B:** 正是，所以你看这套"中断/非中断"的语义是可以横跨好几种事件复用的。现在第二个维度，也是这一段真正要扩容的：边界事件不止能听"消息"。课程在最后一张图上一口气摆了五种触发器——**消息（message）、定时（timer）、错误（error）、信号（signal）、补偿（compensation）**。

**A:** 五种我对一下号：消息边界事件刚讲了，听消息，图标是信封；定时边界事件上一集讲过，听时间到点，图标是时钟；那错误、信号、补偿呢？

**B:** 一个个来。**错误边界事件**——贴在活动上，专门**接住这个活动内部抛出的错误**，图标是个三角/闪电样的标记；这正是你第三种情况"缺货怎么冒出来、谁来接"的答案，我们下一段专门拆它。**信号边界事件**——接住一个**广播出去的信号**；信号和消息的差别在于，消息是**点对点**寄给特定接收方的，信号是**广播**、谁配了对应的接收事件谁都能收到。**补偿边界事件**——图标是个**倒带符号"◀◀"**，它不是用来"接事故"的，而是给某个活动**挂上一段"撤销逻辑"**，标记"这一步将来可以被补救"；这是本集压轴的补偿，最后讲。

**A:** 我先把这一段收一下：边界事件 = 贴在活动边框、活动进行期间监听触发器的圆圈；按"会不会打断"分中断（实线）/ 非中断（虚线）；按"听什么"分消息、定时、错误、信号、补偿五型。它就是舞台剧的后台应急面板。

**B:** 收得干净。而这五个应急按钮里，有两个值得各开一段细讲——**错误**和**补偿**。先按"演砸了怎么急救"的顺序，讲错误。

### 【第五段】台上演砸了：错误事件 Error Event

**B:** 你第三种情况的难点，其实不在"缺货"本身，而在"缺货这件事，发生在**好几层子流程的最里头**，它怎么让外面知道、又该谁来管"。先按你的直觉试试：最里层检查库存发现缺货了，你想怎么把这个消息往外传？

**A:** 我第一反应是……用顺序流一路画出来？从最里层拉一条线，穿过一层层子流程框，连到外面的处理那里。

**B:** 你画画看就知道卡在哪了——子流程的边框是封闭的，顺序流**不能随便穿过子流程的边框**跑出去。而且就算能穿，层层都得手动连线，乱成一团。这正是普通顺序流的死穴：它只会**在同一层里往前走**，不会"向上翻墙"。

**A:** 那……得有一种专门"翻墙上报"的机制。

**B:** 这就是**错误事件**，英文 **Error Event**。课程的引入很直白：**有时候事情会出岔子，我们需要恢复。** 错误事件分两个动作。第一个动作叫**抛出**，英文 **Throw**：在出问题的地方放一个**抛出错误事件**，图标是**实心的闪电/三角**——课程强调一条硬规则：**抛出错误必须带一个标签，标签上是错误码（error code）**，比如"缺货 / not in stock"。

**A:** 必须带错误码……为什么这么强制？

**B:** 因为光喊一声"出错了"没用，得喊清楚"出的是**哪种**错"，外面才知道该派哪套应急方案来接。这就引出第二个动作：**捕获**，英文 **Catch**。捕获靠的就是上一段说的**错误边界事件**，贴在子流程的边框上。课程给了捕获的两条规则，特别精巧：**带标签的捕获事件，只捕获那一个错误码**；**不带标签的捕获事件，捕获任意错误**。

**A:** 哦，所以是"对暗号"——抛出方喊"缺货"，边界上贴着"缺货"标签的那个捕获事件才接得住；要是边界事件不写标签，那就是"什么错我都接"。

**B:** 暗号这个比喻很贴。那现在最关键的问题来了，也是课程专门画了一整张图讲的：**抛出的错误，到底飞到哪去？** 假设缺货发生在子流程 D 里，而 D 套在 C 里、C 套在 B 里、B 套在 A 里……你觉得这个"缺货"错误，会被哪一层接住？

**A:** 我猜……一层层往外冒，碰到第一个写着"缺货"标签的边界事件，就停在那、由它处理？

**B:** 你直接说出了课程的原话级结论：**最近的、带有匹配边界事件的父层，来处理这个错误。** 注意两个词——"最近的"和"匹配的"。错误从抛出点开始**逐层向外传播**（propagation），一边往外冒一边找：这一层的边框上有没有贴着匹配标签的捕获事件？没有就继续往上一层冒；一旦找到匹配的，就停在那一层，由它接管。

**A:** 用舞台剧讲，这就像台上一个演员忘词了——他自己救不回来，这个"事故"就往后台传：先看身边的同台演员能不能接，接不住就传给场边的提词员，再不行传给舞台监督……谁手里正好有这一出的应急预案，谁就接住，传播就停在那。

**B:** 这个层层上报的画面太准了。课程那张图就是用编号 1 到 5 标出传播的层级：缺货在最里层抛出，沿着 D、C、B、A 一层层往外找匹配的"not in stock"边界事件，找到了就由那一层处理。

**A:** 我突然意识到，这跟普通顺序流是两种完全不同的"走法"。顺序流是**水平**的、在同一层往前递令牌；错误传播是**垂直**的、往外层翻墙找接盘的。

**B:** 这个"水平 vs 垂直"概括得绝。记住这一段一句话：**抛出错误必带错误码、像喊暗号；错误向外层逐级传播，被最近的匹配边界事件接住——它是垂直上报，不是水平往前走。**

### 【第六段】返场补救：补偿 Compensation

**B:** 到压轴了。前面五种情况都还在"戏没演完"的范围里——要么停演、要么救场。可你第四种情况彻底跳出去了：**戏已经演完了**——客户付了款、货发了出去——现在他要取消。先问你，这跟"出错"是一回事吗？

**A:** 不是一回事。出错是"**正在做**的时候搞砸了"；这个是"**已经做完、做得好好的**，但现在因为别的原因，得把它**撤回来**"。付款没出错啊，是客户改主意了。

**B:** 你已经摸到了今天最关键的那条分界线。这就是**补偿**，英文 **Compensation**，图标是那个**倒带符号"◀◀"**。课程给它的定义就是：**撤销已经完成的工作。** 注意，是"已经完成的"。用舞台剧讲——前面所有工具处理的都是"**这场戏还在演**"，补偿处理的是"**有一幕已经落幕了，现在要返场，把它的效果补救回来**"，最典型的就是**给观众退票退款**。

**A:** 那我先试试用我现有的工具凑：客户取消了，我就……画个任务叫"退款"、再画个任务叫"收回货物"，接在取消后面？

**B:** 你这个直觉方向是对的——补偿**确实是要画成实实在在的活动**，这点很重要，我等下强调。但你这么硬接会丢掉两个关键信息：第一，这些"退款""退货"在语义上是**绑定到原来那一步**的——退款是冲着"付款"去的、退货是冲着"发货"去的，它们是那两步的"撤销搭档"。第二，它们**平时不演**，只有"取消"这个补偿被触发时才上场。光用顺序流硬接，表达不出这层"绑定"和"待命"的关系。

**A:** 那 BPMN 怎么表达"这是某一步的撤销搭档、平时待命"？

**B:** 这就是**补偿处理器**，英文 **Compensation Handler**。课程讲它的画法，关键两条语法，正好都很反直觉：第一，**补偿处理器用"关联"连接**——还记得我刚才在文本注释那段留的提醒吗？就是那条**点线**。补偿处理器不是用顺序流接到主流程上的，而是用一条**关联线**，挂在它要撤销的那个活动旁边。第二，**补偿处理器没有顺序流进出**——它和事件子流程一样，不在令牌流上，平时悬在那儿待命。

**A:** 哦——点线关联在这儿又出现了！所以补偿处理器跟主流程的关系，不是"下一步"，而是"我是你那一步的撤销搭档，用点线拴着你"。它的触发也不靠令牌走到，而是靠补偿被触发。

**B:** 完全正确。课程把这个机制讲得很清楚：**当那个活动已经做完、然后补偿被触发，补偿处理器就执行。** 三个时序缺一不可——先做完、后触发、才撤销。没做完的活动，没有"已完成的工作"可撤，自然不补偿。

**A:** 那"补偿被触发"具体是怎么发生的？谁来喊这一嗓子？

**B:** 靠一个**抛出补偿事件**。课程讲了它的连接规则，和错误那套异曲同工：**如果从上下文能看清补偿的是哪个，那就不用特别标注；如果有歧义，就给捕获和抛出事件起同一个标签**——又是"对暗号"。课程还补了一条很重要的联动规则：**子流程里一个没被捕获的错误，也会触发该子流程里所有可补偿的活动。**

**A:** 这条联动我得停一下——所以"出错"和"补偿"虽然是两码事，但它们会接上头：如果一个错误在子流程里一路传播、最后**没人接住**，那这个子流程里凡是已经做完、又挂了补偿处理器的活动，都会被自动触发去撤销？

**B:** 正是。你可以理解成：这场子戏彻底崩了、没人能救，那就别留下半拉子的既成事实——把已经造成的效果统统补救回来，干净退场。现在把它落到课程那个采购订单的压轴例子上。主线是一个子流程"处理采购订单"：收到 PO → 检查 PO → 履行 PO（发货）→ 处理付款 → PO 完成。其中**"履行 PO"挂了一个补偿处理器"处理退货"，"处理付款"挂了一个补偿处理器"退款"**，都是用点线关联拴着、平时待命。

**A:** 然后呢，取消怎么进来？

**B:** 旁边一个**事件子流程**——你看，今天的工具开始组合了——由"**收到 PO 取消**"这个触发器启动，里面**抛出一个补偿"取消 PO"**。这一嗓子喊出去，就触发该子流程里所有可补偿活动的处理器：**"退款"把付款撤销、"处理退货"把发货撤销**。

**A:** 我把整条链复述一遍：客户付了款、货也发了——这是两幕已经演完的戏，各自旁边用点线拴着一个返场补救方案，待命。"收到取消"作为一段事件子流程启动，抛出补偿。补偿一触发，两个待命的处理器上场：退款撤付款、退货撤发货。已经落幕的两幕，被一一返场补救回来。

**B:** 教科书级的复述。这里我必须再强调你一开始那个对的直觉：补偿**绝不是"把前面那个任务删掉"**。删掉是假装它没发生过——可它真发生了，钱真付了、货真发了。补偿是**专门建模一段新的、真实的善后活动**去抵消它的效果。退款是一笔真实的财务操作，退货是一趟真实的物流。这就是为什么补偿处理器是一个**实打实的活动**，而不是一个"撤销按钮"。

**A:** 删除是假装没发生，补偿是真做一件事去抵消——这个区别我记牢了。

---

### 【关键辨析】三组最容易栽的区分

**B:** 六件工具齐了。但今天有三组区分，是考试和实战里最容易栽跟头的，我们正面摆一次。第一组你已经会了：**终止 vs 普通结束**——你来。

**A:** 普通结束事件只消耗**到达它的那一个令牌**，别的并行路照走；终止事件**清空当前（子）流程及其所有子流程的全部令牌**，往下全清、往上不动，而且发出坏结局信号、要慎用。一个是单个演员下场，一个是拉幕停演。

**B:** 第二组：**事件子流程 vs 边界事件**——都能处理"中途冒出来的事"，差在哪？

**A:** 差在**附着对象**和**守护范围**。边界事件**贴在某一个具体活动的边框上**，只守这个活动进行的那段窗口，活动一完它就下岗；事件子流程是**整框虚线、搁在整个（子）流程内部**，守的是整场戏运行的窗口，不绑定单个活动。还有个看图的小诀窍：虚线**小圆圈贴在活动边上**是非中断边界事件，虚线**整框独立摆**是事件子流程。

**B:** 第三组，也是今天的灵魂：**补偿 vs 错误处理**。这组最值得说透。

**A:** 我试着分三层说。**第一层，时机不同**：错误处理对付的是"**正在做的时候出了故障**"，补偿对付的是"**已经做完、做得好好的，但现在要撤回**"。**第二层，方向不同**：错误处理是想办法**往前恢复**——救场、走异常路径、继续往下；补偿是**往回抵消**——把已经造成的效果倒带补救。**第三层，手段不同**：错误处理常是转去一条恢复路径；补偿是专门建模一段**真实的善后活动**去抵消，绝不是删掉原任务。

**B:** 三层全中。我再给你一句话把它们焊在舞台剧上：**错误是"台上正演着、某句词演砸了，后台急救让戏接着演下去"；补偿是"某一幕早就落幕了，现在返场把它的效果补救回来、给观众退票退款"。** 一个救正在演的，一个补已经演完的。

**A:** 救现在 vs 补过去。清楚了。

### 【综合应用与习题】从画法到检查站

**B:** 工具讲完，按老规矩用课程的习题当检查站。先看**练习 1**，它其实是来自上一集的多实例，但正好帮你把"画法选择"这件事想透。题目是：收到客户的采购订单请求后，向 **7 家**优选供应商**询价**；收齐所有报价后，选出最优报价、发出订单。要求用两种方式建模：(i) 用 AND 网关，(ii) 用多实例活动。然后问：多实例比 AND 网关好在哪？

**A:** 我先画 (i) AND 网关版：一个 AND 分叉，**拉出 7 条并行分支**，每条一个"向供应商 k 询价"，7 条全收到后用 AND 汇合，再"选最优报价、发订单"。(ii) 多实例版：就**一个活动"询价"，标上多实例的两竖线 ∥**，对 7 家各跑一份实例，并行收齐。

**B:** 那第二问——多实例好在哪？这才是出题人真正想要的。

**A:** 我想到三点。第一，**数量可变**：哪天供应商从 7 家变成 12 家，AND 版得重画 5 条分支，多实例版改个数字、甚至让这个数字由数据驱动就行。第二，**图更干净**：7 条平行线很占地方、很乱，一个多实例标记就收掉了。第三，**语义更准**：多实例本来就是"对一个集合里的每一个，做同一件事"，这正是"给每家供应商询价"的本意；AND 是"做几件**不同**的事"，拿它凑"同一件事做 N 遍"是别扭的。

**B:** 三点抓得很准，尤其第三点——AND 表达的是"不同的并行活动"，多实例表达的是"对集合逐个做同一件活动"，本质不同。这道题的精神是：**画法不是随便选的，它得匹配你要表达的语义。**

**A:** 那源材料里还有两道选作答案，5.2 和 5.3，对吧？我看 PDF 里那两页全是手写、扫描得糊成一团，根本认不出。

**B:** 对，那两页是手绘扫描件，文字提取基本是乱码，所以我们不照着图念，而是用 BPMN 知识把题目本身**口头走一遍建模思路**，权当听众的练习。先看**答案 5.2 对应的练习 2——大学作业流程**：课程协调员决定该换作业了，于是教师**设计作业**，然后**请若干同事评审**，**收齐所有评审**后**据此更新作业**，接着**把作业发给学生**，学生**通过阅读、计算、书写来作答**，之后教师**收集并批改**结果，最后学生**收到分数**；题目说学生可以建模成一个黑盒。

**A:** 我来搭骨架：教师在自己的泳道里，学生建成一个**黑盒池**（black box），两者之间用消息往来。"请同事评审"——若干个同事、做同一件事评审、收齐才继续，这是**多实例 ∥**加上后面的同步。"作业""评审意见"这些是**数据对象**，设计/更新作业时读写它们。从"发作业"到"收答案"是教师和学生黑盒之间的**消息交换**。最后批改、发分数。控制流、组织（泳道/黑盒池）、数据（数据对象）三个视角都得有。

**B:** 骨架很完整。注意题目明确要求"控制流 + 组织 + 数据"三个视角都建模，这正是把前几集的池/泳道、数据对象，和本集多实例焊在一起的练习。再看**答案 5.3 对应的练习 3——诺贝尔化学奖评选**，这道题的灵魂是**时间**。它给了一条横跨一年的时间线：九月**寄出提名表**给约 3000 人；次年一月底**截止收表**，委员会筛选出 250 到 350 个初选名单；三到五月**送交专家评估**；六到八月**撰写报告**；九月**提交建议**、在学院化学组的**两次会议**上讨论；十月**多数表决选出得主**、决定最终且不可上诉、随即公布；十二月十号**颁奖**。

**A:** 这道题我一眼就看到上一集的定时事件该上场了。每个月份的节点，可以用**定时事件**来卡时间——尤其"截止收表"是个典型的时间约束。"寄给 3000 人""送交多位专家"是对一大群对象做同一件事，又是**多实例 ∥**，而且那些被提名人、专家可以建成**黑盒**。"多数表决"选出得主是个 **XOR** 式的结果分流。整条线就是把定时事件、多实例、黑盒池、数据串起来的一个大综合。

**B:** 正是。你看 5.2 和 5.3 虽然图糊了，但思路一点不糊——它们是把第二集到第五集的工具集中拉出来遛一遍：池与泳道、消息、数据对象、多实例、定时事件，再加今天的高级事件意识。

**A:** 我发现今天这六件工具，单看都像"边角料"，可一上真实场景就全冒出来了——停演、加演、批注、应急、报错、补救，缺一件，图就画不全。

**B:** 这正是高级事件的价值：它们不是为了炫技，是为了让你的模型**敢于面对真实业务里那些不顺利的部分**。

### 【总结与 EP06 预告】

**B:** 收尾。今天我们没背工具清单，而是戴着"流程是一场已经开演的舞台剧"这副眼镜，顺着"出意外、要撤销、要善后"一路拆。**拉幕停演**——终止事件，清空整个范围的令牌、发坏结局信号、慎用，跟"只收一个令牌"的普通结束划清界限。**临时加演**——事件子流程，整框虚线、由触发器启动、无进出顺序流，分中断（实线开始）与非中断（虚线开始）。**剧本批注**——文本注释，点线关联、不动令牌流。**后台应急面板**——边界事件，贴在活动边框、活动期间监听，分中断/非中断，能听消息、定时、错误、信号、补偿五种触发器。**台上演砸了**——错误事件，抛出必带错误码、像喊暗号，错误向外层逐级传播、被最近的匹配边界事件接住，是垂直上报不是水平往前。**返场补救**——补偿，撤销已经完成的工作，补偿处理器用点线关联拴着、无顺序流、平时待命，删除是假装没发生、补偿是真做一件善后去抵消。

**A:** 我自己抓三句话拎走：**终止清空整个范围、普通结束只收一个令牌；错误是救正在演的、补偿是补已经演完的；虚线小圆圈贴边是边界事件、虚线整框独立是事件子流程。**

**B:** 这三句拎走，这集就没白听。下一集 EP06，我们要换一个高度——前五集都在练"**怎么把流程画出来**"，攒了一整套 BPMN 词汇；下一集开始问一个更狠的问题：**你画出来的这张图，到底"对不对"？** 我们会从"画得出"走向"画得对"，去碰流程的**正确性与合理性**——比如令牌会不会卡死、会不会有永远跑不完的路、会不会有活动永远轮不到——以及**信号事件**这类把多个流程联动起来的机制。一句话：今天我们让流程**学会了应对意外**，下一集我们要学会**检查这张图本身有没有毛病**。

**A:** 那我先回去，把我那张采购订单图按今天这六件工具补全——尤其那个"付款发货后还能取消"的补偿，我终于知道怎么画了。下集见！

**B:** 下集见。

**[结束音乐]**

**方法论自检：** 启发式四阶段教学（制造困惑→试错→给框架→复述锁定）应用于终止事件、事件子流程、错误传播、补偿处理器等核心概念；段间均用因果桥接而非清单过渡（停演→加演→批注→应急→报错→补救为一条"从没演完到演完"的因果链）；Host A 全程先猜先试、无空洞捧场；三组关键混淆（终止 vs 普通结束、事件子流程 vs 边界事件、补偿 vs 错误处理）设专段正面拆解；术语遵循"中文→English→缩写/标记→通俗解释→例子"协议。
