# EP03 v3.1 — Claude Opus 4.8 Script Generation Prompt

You are writing a Chinese-first bilingual educational podcast script for a BPM university course. This is a complete rewrite — the previous version (v3.0) was 12 minutes and failed the heuristic teaching depth standards. v3.1 must be thorough, exploratory, and properly paced.

## CRITICAL REQUIREMENT: Length

For the source coverage described below (46 content slides, 5 exercises, 4 major conceptual families), the expected runtime is **22-30 minutes**. This means the script should be approximately **100-140 dialogue exchanges** (A/B turns). Do NOT compress — do not skip the struggle phases, do not rush the examples, do not abbreviate the terminology introductions.

## Source Material Coverage

The script must cover ALL of the following from Week 03 lectures:

### 1. RESOURCES (Pages 2-8, 9 slides)
- Pool: models an organisation (independent jurisdiction/territory)
- Lane: models a department or role within an organisation
- Lanes can be nested, can overlap (matrix organisation)
- Collaboration Diagram: process executed with multiple involved parties
- Task in a lane models execution by that lane's role
- Communication: Tokens within pool → sequence flows (solid lines); Tokens between pools → message flows (dashed lines with open arrowhead)
- White-box pool: process fully modelled (lanes, events, tasks, gateways)
- Black-box pool: process not modelled; messages go to/from pool edge
- Nota bene: model organisations/roles, not individuals; model parties without structured process as black boxes (consumers, students); use white boxes only if internal process is interesting for your purpose
- Example: Order-to-Cash with seller (sales + warehouse departments), ERP system, stock check, shipment, invoicing, archiving

### 2. MESSAGES (Pages 2-6, 5 slides)
- Syntax: receiving task, sending task, receiving & sending task, start message event, intermediate receiving message event, intermediate throwing message event, message end event
- Semantics: message models transfer of something; tasks model work — message received BEFORE execution, sent AFTER execution; events model no work
- Messages vs Data: Message is the envelope (communication action), Data is the letter (actual content being transferred)
- Behavioural issues: miscommunication — deadlocks when both pools wait for messages from each other; scenario where buyer sends request quote but seller never receives it
- Deadlock example: two pools each waiting for the other's message before proceeding

### 3. OR GATEWAY (Pages 2-10, 8 slides)
- Syntax: circle inside diamond. Takes decision immediately based on data. Must have conditions on ALL arcs.
- Semantics: 4 scenarios — a∧¬b, ¬a∧b, a∧b, ¬a∧¬b. One or more paths can be activated.
- Default path: need to ensure a∨b (at least one condition true), or indicate default sequence flow with no condition
- OR Join — "Friendly bus driver semantics": driver waits at terminus, checks timetable (upstream activation). Waits for ALL actually-activated tokens before departing. If only one branch was activated, waits for just that one. If both activated, waits for both.
- OR Join undefined/deadlock scenario: two OR joins mutually waiting for each other — OR join 1 waits for token from OR join 2, OR join 2 waits for token from OR join 1. Both stuck.
- Wrap-up: OR joins can merge otherwise unmergeable paths; AVOID OR joins if possible; NEVER make two OR joins dependent on each other; "if someone sells you a tool with full support for OR joins: run away"

### 4. QUALITY (Part 1: Pages 2-16, Part 2: Pages 2-12)
- Models defined by: Syntax (elements + connection rules), Semantics (meaning), Notation (visualisation)
- Textual quality: bad labels undermine credibility ("Me wash too drew An parralel wit languagez")
- FOUR-LEVEL QUALITY PYRAMID:
  - **Structural Correctness** (语法正确性): arcs connect nodes; element-specific rules; start↔end event pairing; start events no incoming SF; end events no outgoing SF; gateways must have >1 incoming OR >1 outgoing SF; XOR arcs must have condition or be default
  - **Behavioural Correctness / Soundness** (行为正确性): data-based gateway conditions; Option to Complete (every instance can eventually complete — no deadlocks/livelocks); No Dead Activities (every activity can be executed by some instance); Proper Completion (no leftover tokens when end event fires)
  - **Semantic Correctness** (语义正确性): does the model express what it's supposed to express? Real-world example: "send goods then receive payment" vs "receive payment then send goods"
  - **Model Conventions** (模型惯例): context-specific rules — syntax restrictions (avoid OR gateways), notation rules (top-left to bottom-right, avoid crossings, split models >30 elements), labelling conventions (activities: imperative verb+noun; events: noun+past participle; conditions: reference data)
- Quality Assurance split: Computers handle Structural + partial Behavioural (syntax checkers, model checking — but BPMN semantics are informal, halting problem); People handle Semantic + Conventions + remaining Behavioural (domain experts, peer modelling, review, sign-off, centre of excellence)

### 5. EXERCISES (5 exercises)
- Exercise 1: Behavioural correctness — loop with XOR, token game analysis
- Exercise 2: Motor claim handling — model with white/black box, Pool/Lane/Message Flow
- Exercise 3: University course organisation — semantic correctness (catering booked before enrollment confirmed), convention improvements
- Exercise 4: Claims processing — SAP system as resource, white/black box decisions
- Exercise 5: Advanced — create three models each violating one behavioural property

## Teaching Methodology — Non-Negotiable

### Central Analogy: MAP (地图)
The episode uses one stable analogy throughout: **drawing a map of a territory**. 
- Pool = country borders
- Lane = provinces/departments within a country
- Sequence Flow = domestic roads (Token can travel freely)
- Message Flow = international bridges (Token cannot cross borders directly — must send a letter/message)
- White-box = detailed map of our country showing every road
- Black-box = just the border outline of another country — we know it exists but don't need its internal roads
- OR Gateway = complex border checkpoint with multiple lanes
- Quality = map inspection — is the grammar right? does every road lead somewhere? does it match reality? is it readable?

This analogy MUST be referenced at every major section transition (at least 5-6 times across the episode).

### Heuristic Teaching 4-Phase Rhythm (apply to EVERY major concept)

**Phase 1 — HUNGER:** Host A expresses genuine confusion, asks a natural question, OR makes an intuitive but flawed attempt. Creates the reason the concept is needed.

**Phase 2 — EXPLORE:** Host B does NOT immediately give the answer. Instead asks "What do you think?" Host A tries to figure it out independently — partially right but incomplete. The failure/partial-success creates appetite.

**Phase 3 — CONSTRUCT:** Only now does Host B deliver the framework with structure, terminology, boundary conditions, and pitfalls. B never speaks more than ~6 lines without an A interjection (clarification, "so you're saying...", edge case probe).

**Phase 4 — ANCHOR:** Host A restates in own words, maps back to the map analogy, and builds a causal bridge to the next concept ("because we now have X covered, the next natural question is Y").

### Architectural Anchoring Rules

After every major section, insert a "map check":
- Where are we now in the big picture?
- What just finished — and why does the next step follow logically?
- How does the coming section connect to the map analogy?

**GOOD bridge:** "We've drawn the country borders. But now we need international bridges — because countries need to send letters to each other. That's where Messages come in."

**BAD bridge:** "OK, Resources done. Now let's talk about Messages."

**Midpoint map check:** At roughly the halfway point, Host A says "Let's pause and review how far we've walked on this map."

### Dual-Host Roles

- **Host A (晓雨):** Learner proxy. Asks what a student would ask. Flags confusion. Restates in simpler words. Is ALSO the discovery catalyst — tries to figure things out before B gives the answer. Serves as comprehension governor: after dense concept clusters, slows down the episode with a natural question or restatement. Never says empty praise ("你讲得太棒了", "这个概念太神奇了").

- **Host B (老师):** Patient expert. Explains, structures, corrects misconceptions. Avoids giving answers too quickly — when A asks a good question, B sometimes responds with another question. Confirms what A got right before supplying what A missed.

### Bilingual Terminology Protocol

Every important English term must be introduced using: 中文 → English → abbreviation → plain Chinese explanation → example sentence.

Example: "这里有一个核心概念：池，英文叫 Pool。不要把它理解成游泳池——在 BPMN 里，Pool 代表一个独立的组织或管辖区域。比如，你的公司和客户公司，就是两个不同的 Pool。"

Do NOT just drop English terms into Chinese sentences without explanation.

### Pacing Ratios

Per concept section: ~15% Hunger/Explore (create appetite), ~65-70% Construct (framework delivery), ~15% Anchor (restate + bridge).

Do not introduce more than one genuinely new framework/term per 12-15 lines of dialogue without a Host A restatement in between.

## Script Structure

1. **Opening problem (Hook):** Host A has drawn a process diagram and it's chaos — everyone thrown into one big pool, no borders, no structure
2. **Episode roadmap:** Tell the listener what they will learn (4 things: borders, bridges, checkpoints, quality inspection)
3. **Resources (Pool/Lane):** HUNGER (A's chaotic diagram) → EXPLORE (A tries color-coding) → CONSTRUCT (B introduces Pool/Lane formally with English terms) → ANCHOR (A restates with map analogy, bridges to "but how do countries communicate?")
4. **Messages:** HUNGER (A asks about cross-border communication) → EXPLORE (A tries drawing solid line across border) → CONSTRUCT (B introduces Message Flow, Message vs Data, behavioural issues) → ANCHOR
5. **OR Gateway:** HUNGER (A encounters complex checkbox scenario) → EXPLORE (A tries XOR, AND — both insufficient) → CONSTRUCT (B introduces OR split, default path, OR join friendly bus driver, deadlock scenarios) → ANCHOR with wrap-up warnings
6. **Midpoint map check:** Host A recaps journey so far
7. **Quality Framework:** HUNGER (A thinks just running syntax checker is enough) → EXPLORE (A tries reasoning about what else could go wrong) → CONSTRUCT (B introduces 4-level pyramid with proper terminology, computer vs human QA split) → ANCHOR
8. **Model Conventions:** CONSTRUCT with examples (labelling, layout, proper completion)
9. **Exercises walkthrough:** Apply all concepts — A plays the token game, makes mistakes, B guides
10. **Episode recap:** Map back to the 4 things promised in the roadmap
11. **Preview:** Next episode (Week 04 — Data & Sub-processes)

## Anti-Patterns to AVOID

- Monologues: B never speaks ≥8 lines without A interjection
- Checklist transitions: "好了X讲完了，现在我们讲Y" → use causal bridges instead
- Analogy disappears mid-episode → reference the map at every major transition
- Host A only says "What's that?" / "Then what?" → A must contribute guesses and syntheses
- Rushing OR join deadlock → this is the key "aha moment" — take time, use the bus driver metaphor carefully
- Compressing quality framework → each of the 4 levels deserves proper Hunger→Explore→Construct→Anchor
- Skipping the computer-vs-human QA split → this is a core insight, not a footnote
