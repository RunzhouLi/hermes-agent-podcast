## 术语与记号

| 中文 | 英文／记号 | 本集含义 |
|---|---|---|
| 串行基准 | serial baseline；T₁(W) | 完成指定任务 W 的合理串行实现，或明确注明口径的并行程序单处理器运行；两者不可暗中替换 |
| 并行运行时间 | parallel runtime；T_N(W) | N 个同速处理器完成同一任务 W 的时间 |
| 墙钟时间 | wall-clock time | 从开始到结束的真实等待；不是把同时发生的各处理器耗时相加 |
| 加速比 | speedup；S(N) | 同一任务的单处理器时间除以 N 处理器时间 |
| 并行效率 | parallel efficiency；E(N) | S(N)/N；不等同于硬件利用率 |
| 线性加速 | linear speedup | S(N)=N；是完全可分、均衡、无开销且处理器有效速度不变的理想参照 |
| 串行比例：串行基准 | serial fraction；s | 串行时间占同一任务 T₁ 的比例，是 Amdahl 参数 |
| 可并行比例：串行基准 | parallelizable fraction；1−s | 单处理器账本中可理想均分的比例 |
| 阿姆达尔定律 | Amdahl’s law | 固定任务、保留串行部分，只缩短可分部分 |
| 并行开销 | parallel overhead；H(N) | 另列的净新增墙钟等待，不能与原账本或重叠部分重复相加 |
| 强扩展 | strong scaling | 总问题规模／工作量固定，改变处理器数，观察完成时间 |
| 弱扩展 | weak scaling | 每处理器有效负担固定，总规模随处理器数增长，观察时间能否保持 |
| 古斯塔夫森定律 | Gustafson’s law | 从放大任务的并行运行，重建同一任务的等价串行工作量 |
| 串行比例：并行运行 | serial fraction in parallel runtime；α / alpha | 串行时间占本次并行总时间的比例，不是 s 的同义符号 |
| 缩放加速比 | scaled speedup；S_G | 放大任务等价单处理器时间除以该任务的并行时间 |
| 缩放加速比对应效率 | E_G=S_G/N | 仍以大任务的等价串行成本为分子；本集用描述性中文名避免误认 |
| 弱扩展时间保持效率 | weak-scaling efficiency；E_weak | 对应小任务单处理器时间除以放大任务多处理器时间，须明确实验口径 |

N 为处理器数。正文中的“人／工作者”是时间账本的比喻，不是人的生产效率测量。s、α、S_G 是数学记号，不是需要另背的英文缩写。

## 公式与完整推理

### 1. 相同任务的基准与指标

先固定任务 W、结果要求、硬件／软件口径及计时边界，再计算：

\[
S(N)=\frac{T_1(W)}{T_N(W)},\qquad
E(N)=\frac{S(N)}{N}=\frac{T_1(W)}{N T_N(W)}.
\]

变快、相同、变慢分别对应 S>1、S=1、S<1。单位相同的时间相除后无量纲。若任务、精度或计时范围变了，仅相除不能把变化归因于并行。

完全理想时 T_N=T₁/N，故 S=N、E=1。该上界依赖工作速率与工作量不变等条件；缓存容量、数据放置或算法变化可能破坏这些假设，不能把模型中的线性上界宣称为所有实验的无条件物理上界。[S03 物理 p4–5；比较口径为教学展开]

### 2. Amdahl：先拆时间，再归一化

令 a 为串行时间，b 为单处理器账本中全部可分工作所需时间：

\[
T_1=a+b,\quad s=\frac{a}{a+b},\quad 1-s=\frac{b}{a+b}.
\]

固定同一任务、同速、理想均分且忽略新增开销：

\[
T_N=a+\frac{b}{N}
=T_1\left(s+\frac{1-s}{N}\right),
\]
\[
S_A(N)=\frac{a+b}{a+b/N}
=\frac{1}{s+(1-s)/N}.
\]

**主账本：**T₁=120 秒，a=30 秒，b=90 秒。

- N=3：T₃=30+90/3=30+30=60 秒；S₃=120/60=2；E₃=2/3≈66.7%。
- s=30/120=1/4。30/60=1/2 是并行运行中的串行等待比例，不是此处的 s。
- N=4：T₄=30+90/4=30+22.5=52.5 秒；S₄=120/52.5=16/7≈2.29；E₄=(16/7)/4=4/7≈57.1%。

三台到四台时完成时间减少，但效率下降；不能把效率下降简单翻译为增加资源完全无用。[S03 物理 p6–7；数值主例来自 C01-K03 详细讲解]

### 3. 渐近上限、有限人数与端点

无开销且 s>0 时：

\[
\lim_{N\to\infty}T_N=sT_1=a,\quad
\lim_{N\to\infty}S_A(N)=\frac1s,\quad
\lim_{N\to\infty}E(N)=0.
\]

当 0<s<1，可分工作仍为正；任何有限 N 都有 b/N>0，因此 T_N>a、S_A(N)<1/s。主账本加速趋近 120/30=4，不等于 N=4 时达到 4 倍。

端点必须另说：s=1 时全串行，S=1，任意有限 N 已等于这个上限；s=0 且其他理想条件持续成立时，S=N、E=1，不适用“正串行瓶颈下效率趋零”的结论。

**原课件 5% 串行例的可重建账本：**任选 T₁=100 秒，则 a=5 秒、b=95 秒。这是归一化选择，不是课件给出的一次机器测量。

| N | 等待时间 T_N=5+95/N（秒） | 加速比 100/T_N | 对比意义 |
|---|---|---|---|
| 4 | 115/4=28.75 | 80/23≈3.48 | 有串行部分，不到 4 倍 |
| 20 | 39/4=9.75 | 400/39≈10.26 | 20 个处理器不等于 20 倍 |
| 100 | 119/20=5.95 | 2000/119≈16.81 | 仍低于渐近上限 20 |

上限 1/0.05=20；表中有限 N 的数字是教学计算，不声称是课件曲线逐点读数。正文只展开 N=20，避免一次记多组结果。[S03 物理 p7–8]

### 4. 净开销另列，不能重复计入 s

\[
T_N=a+\frac bN+H(N),\qquad
S(N)=\frac{a+b}{a+b/N+H(N)}.
\]

H(N) 是没有包含在原账本、且未被其他工作重叠遮住的净新增等待。若 H(N)≥0，则该任务实际加速不高于相应无开销模型；但只测一个 N 的 H，不能推断所有规模的真实极限。

主例 N=3，H(3)=6 秒：T₃=30+90/3+6=66 秒；S₃=120/66=20/11≈1.82；E₃=(20/11)/3=20/33≈60.6%。六秒已是整个并行运行的新增墙钟时间，不再除以三；也不把它同时加入原 s。

不同计时项可能重叠，不能把所有通信、CPU、等待计数直接相加。仅凭总时间也不能唯一诊断瓶颈。[C01-K03 详细讲解；在 S03 p6–8 理想模型上的展开]

### 5. 强扩展与弱扩展：设计不同于结果

- 强扩展：W 固定，考察 T(N,W)。同一任务增人后时间不变，意味着没有完成时间上的加速。
- 弱扩展：令 q 表示每处理器的有效可分负担，按 W_N≈Nq 扩大规模，再观察 T(N,W_N)。时间稳定是理想结果，不是实验必须满足的定义。
- 记录条数相同，未必计算负担相同；应检查每条记录的计算成本、复杂度和结果要求。
- 总任务里还可有共同准备、汇总、通信等成本，这些成本不必随 N 成比例，因此不应从“每处理器有效负担固定”推断“所有阶段总工作量都恰好乘 N”。

[S03 物理 p10；固定时间示意的定义边界结合 C01-K04 展开]

### 6. Gustafson：从并行等待重建等价工作

本节用 c 表示每个处理器在并行阶段完成的有效工作时间，避免与上一节串行账本中的全部可分工作 b 混淆。设共同串行时间为 a、并行总时间 τ=a+c，忽略额外开销并保持同速与负载均衡：

\[
\alpha=\frac a\tau,\quad
T_{1,\mathrm{scaled}}=a+Nc
=\alpha\tau+N(1-\alpha)\tau.
\]
\[
S_G=\frac{T_{1,\mathrm{scaled}}}{\tau}
=\alpha+N(1-\alpha)=N-(N-1)\alpha,
\]
\[
E_G=\frac{S_G}{N}=(1-\alpha)+\frac\alpha N.
\]

**四人十分钟主例：**a=1 分钟，c=9 分钟，N=4。

1. τ=1+9=10 分钟。
2. T₁,scaled=1+4×9=37 分钟。不能用 4×10=40，因为共同串行阶段只执行一次。
3. α=1/10。
4. S_G=37/10=3.7，也等于 4−3×(1/10)=3.7。
5. E_G=(37/10)/4=37/40=92.5%。

α 固定且 α<1 时，S_G 随 N 线性增长，斜率为 1−α；α=1 时全串行，S_G 恒为 1。固定 α 时 E_G 趋于 1−α，不自动趋于 1。α 固定只规定比例，不推出 τ 固定，也不推出串行墙钟时间 ατ 消失。“串行越来越不重要”指其在增长的等价串行工作量中的相对权重下降；这仍依赖存在可增长的并行工作。数据规模增大不自动消除通信、汇总、内存和负载约束。[S03 物理 p11–12；数值例来自 C01-K04 详细讲解]

### 7. s 与 α 的分母转换

仅在**同一任务、同速、理想均分、同一串行阶段且无额外开销**的模型中：

\[
s=\frac{a}{a+Nc}
=\frac{\alpha}{\alpha+N(1-\alpha)},
\]
\[
\alpha=\frac{a}{a+b/N}
=\frac{s}{s+(1-s)/N}.
\]

主例 α=1/10，N=4：

\[
s=\frac{1/10}{1/10+4\times9/10}=\frac1{37}.
\]

将同一大任务的 s 代入 Amdahl：

\[
S_A(4)=\frac1{1/37+(36/37)/4}
=\frac1{10/37}=\frac{37}{10}=3.7.
\]

或直接使用时间账本：T₄=1+36/4=10 分钟。反向换算：α=(1/37)/(10/37)=1/10。两定律描述同一任务时相容，不可把 α 的数值未经转换就当作 s。

固定任务增大 N，s 可固定而 α 改变；Gustafson 的固定 α 则通常在考察改变规模的一组任务。若另有开销，必须说明分解口径，不能不加修改地把开销当有效工作后套这组换算。[S03 物理 p7、p11–12；分母联系来自 C01-K04 详细讲解]

### 8. 缩放效率与弱扩展时间比不是一个量

明确标注大小任务：

\[
E_G(N)=\frac{T_{1,\mathrm{large}}}{N T_{N,\mathrm{large}}},
\qquad
E_{\mathrm{weak}}(N)=\frac{T_{1,\mathrm{small}}}{T_{N,\mathrm{large}}}.
\]

后式适用于已说明每处理器有效负担对应关系的实验系列。它不是 S03 p12 的 E_G 的同义改写。

主例补充小任务：单人共同准备 1 分钟、有效计算 9 分钟，T₁,small=10；四人处理大任务仍 T₄,large=10。

- E_G=37/(4×10)=37/40=92.5%，分子为**大任务等价单人时间**。
- E_weak=10/10=1，分子为**小任务单人时间**。

若只给“四人十分钟”，没有小任务基准，就不能算第二个量。若同一有效工作另增加 2 分钟净开销，大任务变为 12 分钟：

- 时间比变为 10/12=5/6≈83.3%。
- 若大任务等价有效串行工作仍为 37 分钟，实际加速比对应效率应重新算为 37/(4×12)=37/48≈77.1%，不能沿用 92.5%。此时不能把带开销的并行时间直接当无开销 Gustafson 时间分解。

[课件效率来自 S03 物理 p12；弱扩展时间比及区别为本集的指标口径补充，不冒充该页另给了一条同义公式]

## 分题练习：先题目，后提示，最后答案

所有题均为教学自编，不是 Moodle 测验、课程官方试题或官方答案。除明确的计时差异或开销外，任务、结果要求和处理器有效速度按题目保持一致。各独立变式使用不同于讲解主例的时间账本；报告二的第二、第三步故意沿用第一步数据，逐步检查同一任务的不同推理。

### 练习一：统一比较口径（O1；S03–S06）

**问题**

同一任务、同一结果要求。单处理器完整时间 80 秒；四处理器计算阶段 32 秒；另有未计入、且不重叠的前后处理合计 8 秒。求可比较的加速比与效率，并说明为何不能只用 32 秒。算完后判断：所得效率能否直接当成每台处理器的硬件利用率？说明理由。

**作答顺序**：暂停求完整等待时间 → 再暂停求加速比 → 再求效率 → 最后另暂停，解释效率与硬件利用率能否直接等同。对应作答章节 S04。

**可选提示**

1. 两段先后发生，应先补齐计时范围。
2. 加速比分子是完整单人时间；效率再除以处理器数。

**答案与理由**

\[
T_4=32+8=40\text{ 秒},\quad
S=80/40=2,\quad E=2/4=1/2=50\%.
\]

只用计算阶段，会把端到端时间与局部时间比较。效率不是任一处理器的利用率：这里只用了完整等待时间与处理器数，没有测量各处理器何时忙闲；执行额外代码也可能让机器很忙。如果任务或精度不一致，单靠补齐这 8 秒仍不能使比较公平。

**常见误答**：用 80/32 作为端到端加速比；把四处理器的完整等待再除以四；由 E=50% 断言每个处理器恰有一半时间空闲。

**达到目标的证据**：写出一致计时边界、正确比值方向和人数归一化，能说明利用率并非该公式的直接结论。

### 练习二：同任务的串行分母（O2；S08–S11）

**问题**

单处理器 84 秒，其中串行 12 秒、可分 72 秒。N=3，无开销、理想均分。求并行时间和 Amdahl 的 s，用完整一句话说明 s 的分母。

**作答顺序**：暂停重建时间 → 再暂停标出比例分母。对应作答章节 S09。

**可选提示**

1. 只均分可分工作。
2. s 描述同一任务在单处理器账本里的结构。

**答案与理由**

\[
T_3=12+72/3=12+24=36\text{ 秒},\qquad
s=12/84=1/7.
\]

12/36=1/3 是三处理器运行中的串行等待比例，不是 s。它是另一个有意义的比例，错误在于将其放进不匹配的公式，而不是这个除法本身无意义。

**常见误答**：T₃=84/3；s=12/36。

**达到目标的证据**：保留串行段、只均分可分段，并明确分母是“同一完整任务的单处理器时间”。

### 练习三：先看固定量（O4；S15–S18）

**问题**

一处理器处理 10 个模拟用 100 秒；四处理器处理 40 个模拟用 130 秒。每个模拟计算成本相同、每处理器均分，结果要求不变。判断扩展类型；时间增长会不会改变实验类型？

**作答顺序**：先判固定量，再解释时间表现。对应作答章节 S16。

**可选提示**

先比较每处理器的有效模拟数，再区分“怎样设计实验”和“希望时间怎样表现”。

**答案与理由**

\[
10/1=10,\qquad 40/4=10.
\]

每处理器负担固定，总规模扩大，因此是弱扩展。100 秒到 130 秒说明时间没有理想保持，不会把弱扩展实验变成强扩展。若总规模固定才是强扩展；不能仅凭时间曲线的形状命名。

**常见误答**：“时间增加，所以不是弱扩展”；“用了更多处理器，所以就是强扩展”。

**达到目标的证据**：引用工作量与处理器数的关系命名，再独立评价时间结果。

### 练习四：给分子贴任务标签（O7；S23–S26）

**问题**

已确认是每处理器有效负担相同的弱扩展系列，汇总成本允许变化。小任务单处理器 8 分钟；大任务三处理器 10 分钟；大任务单处理器完整时间另已核实为 22 分钟。分别计算缩放加速比对应效率、弱扩展时间比，并标注分子属于哪份任务。

**作答顺序**：先单独计算大任务加速与效率；另起一行计算小到大的时间保持。对应作答章节 S24。

**可选提示**

1. 第一种先比较同一大任务的单人与三人时间，再除以人数。
2. 第二种分子换成小任务单人时间，不再除以三。

**答案与理由**

\[
S_{\mathrm{large}}=22/10=11/5=2.2,
\]
\[
E_G=(22/10)/3=22/30=11/15\approx73.3\%,
\]
\[
E_{\mathrm{weak}}=8/10=4/5=80\%.
\]

前者分子为大任务串行 22 分钟，后者分子为小任务串行 8 分钟，分母口径也不同。共同设置、汇总等成本不必按人数复制，故不能从每人负担相同推断 T₁,large=3×T₁,small。本题不要求由这些汇总时间反推唯一的串行／并行分解。

**常见误答**：两个指标都用 22 分钟作分子；对弱扩展时间比再除以三；把两个不同百分比当成矛盾。

**达到目标的证据**：两项数值均正确，且用“小任务／大任务”解释分子差别。

### 报告一：分清有限值、上限与开销（O3，兼练 O1/O2/O4；S27–S30）

**问题**

始终同一批模拟。T₁=160 秒，其中串行 40 秒、可分 120 秒。N=4，另有 10 秒未计入前项且未重叠的净开销。报告声称：“串行比例的倒数为四，所以四处理器就能实现四倍加速。”请分步求实际时间、加速比、效率，再判断该结论。

**作答顺序**：实际时间 → 用实际时间求指标 → 单独解释理想上限。每一步按暂停键，不必同时记住所有待求量。对应 S28。

**可选提示**

1. 只均分可分的 120 秒；新增净等待另列。
2. 指标须使用实际完整时间，不能挑更短的无开销中间值。
3. 上限先忽略开销，观察可分等待趋近零时还剩什么；不要把渐近过程当成有限人数。

**答案与理由**

\[
T_{4,\mathrm{ideal}}=40+120/4=40+30=70\text{ 秒},
\]
\[
T_{4,\mathrm{actual}}=70+10=80\text{ 秒},\quad
S=160/80=2,\quad E=2/4=1/2=50\%.
\]
\[
s=40/160=1/4,\quad
\lim_{N\to\infty}S_{A,\mathrm{ideal}}(N)=1/s=4.
\]

实验固定总任务，属强扩展。有限四处理器仍有 30 秒可分计算等待，即使不计额外开销，也只有 160/70=16/7≈2.29 倍，不到 4 倍。新增开销后实际是 2 倍。模型的 4 倍渐近上限不是“四台即可实现”的保证；仅知道 H(4)=10 秒，不能推断 H(N) 随规模怎样变化，也不能断言真实系统必定趋近 4 倍。

**常见误答**：把 160 整除以四再加十；把 H 重复并入 s；用 70 秒计算“实际”加速；将上限数当处理器数。

**达到目标的证据**：分别给出 70 秒理想有限值、80 秒含开销值及 4 倍渐近上限，解释三者不是同一状态。完成后收起本报告再进入下一份。

### 报告二·第一步：还原工作量（O5；S31–S34）

**问题**

五个同速处理器完成一份放大任务用 12 分钟，其中共同串行准备与收尾 2 分钟；其余 10 分钟，每个处理器都做独立有效计算。无额外开销、负担均衡。求等价单人时间，再求缩放加速比。此步先不求串行比例。

**作答顺序**：暂停摊开有效工作 → 再除以本次并行总时间。对应 S32。

**可选提示**

共同两分钟只发生一次；每份十分钟的并行有效工作才应按五份相加。

**答案与理由**

\[
T_{1,\mathrm{large}}=2+5\times10=52\text{ 分钟},
\]
\[
S_G=52/12=13/3\approx4.33.
\]

分子 52 分钟是这份大任务的等价串行成本。不能写 5×12=60 分钟，因为这会复制共同串行阶段。若计算阶段含等待或冗余工作，也不能全部直接乘五当作有效成果；本题明确排除了这些情况。

**常见误答**：等价单人时间为 60 分钟；因用了五处理器就直接写五倍。

**达到目标的证据**：串行只算一次、有效并行工作按五份还原，分子分母对应同一大任务。

### 报告二·第二步：检查分母转换（O6；S35–S38）

**问题**

继续同一份报告，现在把已完成的上一步结果作为已知量：串行 2 分钟、五处理器总时间 12 分钟、等价单人总时间 52 分钟。求 α 和 s，并按 Amdahl 的账本反算五处理器时间，检查与原报告是否一致。

**作答顺序**：暂停选 α 分母 → 暂停选 s 分母 → 暂停回算时间。对应 S36。

**可选提示**

1. 分子都是两分钟；α 参照并行总等待，s 参照同任务单人总时间。
2. 单人 52 分钟扣去串行段后，剩余部分才允许均分。

**答案与理由**

\[
\alpha=2/12=1/6,\qquad s=2/52=1/26.
\]

直接时间账本：

\[
T_5=2+(52-2)/5=2+50/5=12\text{ 分钟}.
\]

公式交叉检查：

\[
s=\frac{1/6}{1/6+5\times5/6}=1/26,
\]
\[
S_A(5)=\frac1{1/26+(25/26)/5}
=\frac1{6/26}=13/3=S_G.
\]

反向换算：

\[
\alpha=\frac{1/26}{1/26+(25/26)/5}
=\frac{1/26}{6/26}=1/6.
\]

**常见误答**：把 α=s=1/6；把比例数值不同当成模型矛盾；换算时偷偷换成小任务。

**达到目标的证据**：正确解释两个分母，使用同一大任务重建 12 分钟，并恢复与第一步相同的加速比。

### 报告二·第三步：识别缺失数据（O7 补充检查；S39–S42）

**问题**

现有信息只有五处理器这一行，以及据此重建的大任务单人时间。能否求弱扩展效率的时间比？能否仅凭这一行确认整个实验采用弱扩展设计？分别指出所缺信息，不猜数字。

**作答顺序**：先写指标完整标签，再检查已知量；最后检查实验设计。对应 S40。

**可选提示**

52 分钟属于大任务。弱扩展时间比分子属于哪份任务？判断扩展类型又需要哪些规模之间的关系？

**答案与理由**

不能给出数值时间比，因为缺少对应小任务的一处理器时间 T₁,small；52/12 是大任务的缩放加速比，不是弱扩展时间保持效率。也不能仅凭一个 N 的运行确认扩展设计：还需其他规模的实验记录及每处理器有效负担保持的说明。

**常见误答**：用 52/12 冒充弱扩展效率；把小任务时间猜成 12；由“放大任务”或“Gustafson”这个名称就断言整组实验是弱扩展。

**达到目标的证据**：不编造缺失量，分别说出缺少小任务时间与缺少跨规模工作量关系。

## 精确分数核算

以上有数值答案的步骤以 Python `fractions.Fraction` 精确复算，再按正文需要舍入；不是机器基准测试。以下可重复运行的断言覆盖主例、5% 例、所有数值变式、两报告及双向分母转换。

```python
from fractions import Fraction as F

def fixed(a, b, n, h=0):
    t = F(a) + F(b, n) + F(h)
    speed = F(a + b) / t
    return t, speed, speed / n, F(a, a + b)

assert fixed(30, 90, 3) == (F(60), F(2), F(2, 3), F(1, 4))
assert fixed(30, 90, 4) == (F(105, 2), F(16, 7), F(4, 7), F(1, 4))
assert fixed(30, 90, 3, 6) == (F(66), F(20, 11), F(20, 33), F(1, 4))
for n, speed in ((4, F(80, 23)), (20, F(400, 39)), (100, F(2000, 119))):
    assert fixed(5, 95, n)[1] == speed
assert F(1) / F(5, 100) == 20
assert (F(32) + 8, F(80, 40), F(80, 40) / 4) == (F(40), F(2), F(1, 2))
assert (fixed(12, 72, 3)[0], fixed(12, 72, 3)[3]) == (F(36), F(1, 7))
assert F(12, 36) == F(1, 3)
assert F(10, 1) == F(40, 4) == 10
assert (F(22, 10) / 3, F(8, 10)) == (F(11, 15), F(4, 5))
assert fixed(40, 120, 4, 10) == (F(80), F(2), F(1, 2), F(1, 4))
assert fixed(40, 120, 4)[0] == 70

for a, c, n, serial, speed in ((1, 9, 4, 37, F(37, 10)), (2, 10, 5, 52, F(13, 3))):
    tau = F(a + c)
    assert F(a) + n * c == serial
    alpha, s = F(a) / tau, F(a, serial)
    assert F(serial) / tau == alpha + n * (1 - alpha) == speed
    assert s == alpha / (alpha + n * (1 - alpha))
    assert alpha == s / (s + (1 - s) / n)
    assert 1 / (s + (1 - s) / n) == speed
    assert F(a) + F(serial - a, n) == tau
assert (F(37, 10) / 4, F(10, 10), F(10, 12)) == (F(37, 40), F(1), F(5, 6))
assert F(37, 12) / 4 == F(37, 48)
assert (F(2, 12), F(2, 52)) == (F(1, 6), F(1, 26))
print("Fraction checks passed")
```
